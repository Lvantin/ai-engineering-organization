# Project Onboarding Workflow

**Version:** 1.0.0 | **Status:** Draft

## Trigger
A new project adopts AIEO or an existing project is onboarded to a new AIEO release.

## Steps
1. Confirm project sponsor, goals, scope, repositories, and access boundaries.
2. Create or inspect project entry point and project profile.
3. Discover applications, services, repositories, technology stacks, and environments.
4. Inspect architecture, contracts, data ownership, and dependencies.
5. Identify engineering, quality, security, and operational constraints.
6. Classify findings as Verified, Inferred, Assumed, or Unknown.
7. Create a gap list and prioritize critical missing context.
8. Establish Product backlog and initial Feature structure.
9. Prepare Feature 0 technical foundation scope.
10. Obtain human confirmation for material assumptions and project decisions.
11. Record adopted AIEO version and onboarding completion evidence.

## Exit criteria
Project purpose, scope, ownership, system inventory, key dependencies, development approach, and major risks are sufficiently understood to plan the next work safely.
